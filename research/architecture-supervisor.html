Checker implementation: code always validates schema, IDs, query scope and limits. A separate review call handles relevance and claim support when needed. It sees the task and source records, not just the investigator's summary. The same checker pattern covers analyst and writer tasks; it is not a permanently running extra agent per worker.

A monitor reduces unsupported claims; it cannot guarantee correctness or zero hallucinations. Test whether local checking helps, and count its extra tokens and latency.

05 · How delegation works

Yes: expose agents as callable tools.

delegate(expert, question, tentative_scope, evidence_refs, budget)
→ task_id → completion event { findings, source_ids, counterevidence, gaps, status, next_requests }

The runtime schedules the specialist's bounded investigation, streams task completion, and runs independent tasks concurrently. The orchestrator may revisit the same specialist with a revised question. Findings are written incrementally; other tasks wait only on explicit dependencies.

Capability catalogWhat each expert can investigate and which sources exist. No answer-specific scenario scripts.
Shared evidenceOne traceable record; source IDs and revisions prevent summaries being mistaken for new evidence.
Runtime supervisorCode enforces timeouts, retries, concurrency and global call/token/time budgets—even for checker calls.
Explicit stopsReviewed support, clarification needed, no useful next query, unavailable evidence, or budget exhaustion.

The reasoning agent is the callable hypothesis analyst; the reporting agent drafts the report. Keeping these responsibilities explicit covers the brief while the orchestrator focuses on planning and control.

06 · Variants of this proposal

A1 · Central task routing

All cross-expert requests go through the orchestrator. Experts choose their own queries and propose follow-ups. One place tracks dependencies and total budgets.

A2 · Experts delegate directly

An expert can call another expert. It may shorten handoffs, but nested work makes ownership, cycles and total budgets harder to control. The same runtime would still need to own every task.

Research basis and remaining decisions

This is our proposal. incident.io describes revisable evidence-backed findings and adversarial review; Resolve describes focused parallel investigators and independent verifiers. Neither source establishes this exact per-specialist checker architecture. Next decisions: task/evidence schemas, checker policy, concrete budgets, and implementation framework.

Evaluate with at least 10 incidents and a same-tools single-agent baseline: accuracy, grounding, attempted tool calls, wall-clock latency, and all-model tokens. Track review-call count separately and test with/without local checks. No performance advantage is assumed.
