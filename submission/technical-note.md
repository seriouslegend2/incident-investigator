# Technical note

The system investigates a vague operational complaint by retrieving evidence instead of placing a whole repository, database or log archive into a model prompt. D1 is a control-plane orchestrator: it queries a small service/dependency index, chooses only relevant specialists, and starts independent tasks in parallel. D3 examines bounded observability slices; D4 maps code and deployment paths from an approved checked-out revision; D5 reads contract-scoped data through a read-only backend; and D6 examines AI-run, prompt, retrieval and tool-handoff records. D7 challenges citations, scope and unsupported claims, and can request a precise follow-up through D1. D8 writes only from reviewed findings.

This separation improves traceability and least privilege. A database specialist cannot construct arbitrary SQL, and a code specialist cannot run shell commands or scan an unbounded filesystem. Each evidence read has a case, task and agent-run identity and is stored in the investigation ledger. LangSmith records an individual root `agent/<role>/<operation>` trace per invocation; it shows that agent's exact prompt, scoped input, allowed tools, structured result and handoff, with nested model and tool spans. The separate roots retain the same case/task/agent-run metadata for correlation. Versioned prompts are also published from the codebase.

The central trade-off is cost and latency. More specialists and criticism provide stronger cross-checking than a single unrestricted model, but consume more tool calls and tokens. Parallel fan-out reduces wall-clock latency when tasks are independent; it does not make causality automatic. Source gaps, trace sampling and replica freshness must remain explicit limitations, and an inconclusive report is preferable to a plausible invented root cause.

The runnable demo uses one pinned local reference repository and synthetic Supabase records. It is not yet a billion-scale source platform. Production would add incremental code, topology, telemetry, data-catalog and AI-trace indexes behind the same bounded adapters, with durable queues, global budgets and source-specific read identities. Remaining work includes a dedicated historical-incident connector, replayable tool failures and an equal-tools single-agent evaluation. Those gaps are documented rather than represented as completed features.
